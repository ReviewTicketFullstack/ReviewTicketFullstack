# design.md — ReviewTicket 디자인 가이드

이 문서는 **디자인 규칙만** 정의한다. 컴포넌트 구현·페이지·비즈니스 로직은 포함하지 않는다.
모든 신규 UI 작업은 구현 전에 이 문서를 먼저 따른다. **이 문서가 시각 디자인의 Source of Truth다.**

- 대상 스택: React 19 · Vite · **Tailwind CSS v4** · react-router-dom v7
- Tailwind v4에는 `tailwind.config.js`가 없다. 토큰은 **`src/index.css`의 `@theme`에서만** 선언한다.
- 색·타이포·그림자·아이콘 조형은 배달앱 계열 레퍼런스에서 도출했다. 원본 아카이브는 `claude/design-reference-yeogi.md`에 있으나 **참조할 필요는 없다.** 이 문서만으로 자립한다.

# Brand & Tone

- **정서**: 친근하고 활기찬 배달 서비스. 밝고 유쾌하되 과장하지 않는다.
- **강조 전략**: 화면의 강조는 **빨강 계열 accent 하나로 수렴**시킨다. 강조가 흔해지면 강조가 아니다.
- **핵심 기능 우선**: 이 서비스의 차별점은 리뷰 이벤트/티켓이다. 화면에서 가장 눈에 띄어야 할 요소는 이것이며, accent는 여기에 먼저 배정한다.
- **밀도**: 커머스형 조밀한 밀도를 따른다. 타입 스케일 상한은 32px이고 데스크톱 히어로급(48px+) 단계를 두지 않는다.
- **금지 톤**: 보라색 그라디언트, glassmorphism, 과도한 glow, 미래지향 스타일. 이 서비스의 톤이 아니다.

# Design Principles

1. **Mobile-first** — 무접두사 클래스가 모바일 기준이다. `sm:` `md:` `lg:`는 화면이 커질 때만 덧붙인다.
2. **Responsive layout** — 고정 px 폭을 쓰지 않는다. 폭은 유동으로 두고 `max-w-*`로만 상한을 건다.
3. **Consistent spacing** — 아래 Spacing 스케일 밖의 값을 쓰지 않는다. 임의 값(`p-[13px]`)은 금지.
4. **Reusable components** — 같은 UI가 두 번째로 필요해지면 `src/shared/ui/`로 올린다. 처음부터 추상화하지 않는다(YAGNI).
5. **Accessibility where practical** — 필수 4가지: 터치 타깃 최소 44×44px, 아이콘 단독 버튼에 `aria-label`, 포커스 링 제거 금지, 정보를 색으로만 전달하지 않기.
6. **Keep the UI simple** — 정보 위계는 색·그림자보다 **여백과 굵기**로 만든다.
7. **Avoid unnecessary visual complexity** — 장식용 애니메이션, 배경 패턴, 불필요한 구분선을 넣지 않는다.

# Colors

## 시맨틱 역할

**컴포넌트에는 역할 이름만 등장한다.** hex를 컴포넌트에 직접 쓰면 규칙 위반이다.

| 역할                   | 매핑          | 사용처                                  |
| ---------------------- | ------------- | --------------------------------------- |
| **Primary**            | `brand-800`   | 주요 버튼, 활성 탭, 강조 배지, 포커스   |
| **Primary Subtle**     | `brand-50/100`| Primary의 연한 배경(선택 칩, 강조 블록) |
| **Primary Foreground** | `white`       | Primary 배경 위 텍스트·아이콘           |
| **Background**         | `surface-sub` | 페이지 바탕                             |
| **Surface**            | `white`       | 카드, 헤더, 바텀 내비, 모달 패널        |
| **Border**             | `line-100`    | 인풋 테두리, 사이드바 구분, 정적 카드   |
| **Text**               | `ink-900`     | 제목, 본문                              |
| **Text Secondary**     | `ink-700`     | 부가 설명                               |
| **Muted**              | `ink-500`     | 메타 정보, 비활성 탭, placeholder       |
| **Danger**             | `brand-900`   | 삭제, 인풋 에러, 에러 메시지            |
| **Success**            | `green-700`   | 완료 상태 배지, 성공 안내               |
| **Rating**             | `star`        | 별점 아이콘 전용                        |

> **Danger 주의** — Primary가 이미 빨강이라 Danger를 같은 값으로 두면 구분이 사라진다. Danger는 더 어두운 `brand-900`을 쓰고, **반드시 아이콘이나 문구를 동반**해 색만으로 구분되지 않게 한다.

## 토큰 정의

구현 시점에 아래 블록을 `src/index.css`의 `@theme`에 **한 번만** 선언한다. 기본 유틸리티를 덮어쓰지 않도록 신규 이름만 쓴다.

```css
@theme {
  /* Accent — 강조는 brand-800 하나로 수렴 */
  --color-brand-50: oklch(0.978 0.011 17.3); /* #FFF5F5 */
  --color-brand-100: oklch(0.96 0.02 28.9); /* #FFEDEA */
  --color-brand-800: oklch(0.65 0.22 27.9); /* #F94239 — Primary */
  --color-brand-900: oklch(0.598 0.232 29.6); /* #EA2013 — Danger */

  /* Neutral */
  --color-ink-900: oklch(0.252 0 0); /* #222222 */
  --color-ink-700: oklch(0.475 0 0); /* #5C5C5C */
  --color-ink-500: oklch(0.637 0 0); /* #8B8B8B */
  --color-ink-300: oklch(0.792 0 0); /* #BBBBBB */
  --color-line-100: oklch(0.925 0 0); /* #E6E6E6 */
  --color-fill-100: oklch(0.97 0 0); /* #F5F5F5 — Muted 배경 */
  --color-surface: oklch(1 0 0); /* #FFFFFF */
  --color-surface-sub: oklch(0.985 0 0); /* #FAFAFA */

  /* 상태 */
  --color-green-700: oklch(0.64 0.124 172.3); /* #01A484 — Success */
  --color-star: oklch(0.827 0.171 80.5); /* #FFB803 — 별점 */
}
```

## 규칙

- **강조는 Primary 하나로 수렴시킨다.** 보조 강조색을 새로 만들지 않는다.
- **유채색의 투명도를 임의로 조정하지 않는다.** 연한 빨강이 필요하면 `brand-800/20`이 아니라 `brand-50` / `brand-100`을 쓴다. 투명도가 허용되는 것은 무채색(오버레이·그림자)뿐이다.
- Background와 Surface는 항상 구분되게 둔다. 둘이 같으면 카드가 사라진다.
- Danger / Success는 **상태 전달에만** 쓴다. 장식이나 강조 용도로 전용하지 않는다.
- 색으로만 정보를 전달하지 않는다. 항상 텍스트나 아이콘을 동반한다.
- 그라디언트를 쓰지 않는다. 배경은 단색이다.
- **대비 한계 인지** — 흰 배경 위 `brand-800`은 약 3.6:1로 작은 텍스트 기준 WCAG AA에 미달한다. 12px 이하 텍스트를 Primary 단색으로 두지 말고, 아이콘을 병기하거나 `brand-900`을 쓰거나 Primary 배경 + 흰 전경으로 뒤집는다.
- 다크 모드는 MVP 범위 밖이다. 역할 이름 체계를 지키면 나중에 값 교체만으로 대응된다.

# Typography

## 서체

```css
--font-sans:
  "Pretendard Variable", Pretendard, -apple-system, "Apple SD Gothic Neo", system-ui, sans-serif;
```

국문·영문·숫자를 한 서체로 통일한다. 숫자 전용 서체를 따로 두지 않는다. 웹폰트 로드 전까지는 시스템 폰트로 폴백하며, 이는 의도된 동작이다.

## 스케일

5종만 쓴다. 이 밖의 텍스트 스타일을 새로 만들지 않는다.

| 역할              | 클래스                          | px    | 용도                          |
| ----------------- | ------------------------------- | ----- | ----------------------------- |
| **Page Title**    | `text-xl font-bold`             | 20    | 화면당 1회. 페이지·모달 제목  |
| **Section Title** | `text-base font-bold`           | 16    | 섹션 헤딩, 카드/리스트 제목   |
| **Body**          | `text-sm`                       | 14    | 본문 기본값                   |
| **Caption**       | `text-xs`                       | 12    | 메타 정보, 도움말, 에러       |
| **UI Label**      | `text-xs font-semibold`         | 12    | 버튼, 탭, 배지 등 컨트롤 라벨 |

## 규칙

- 굵기는 `font-normal` / `font-semibold` / `font-bold` 세 단계만 쓴다.
- **컨트롤 텍스트는 본문 스케일과 분리한다.** 버튼·탭·배지 라벨은 UI Label(항상 `font-semibold`)을 쓴다. 굵기를 상황마다 바꾸지 않는다.
- **`tracking-*`(자간)을 지정하지 않는다.** 기본값을 쓴다.
- 줄바꿈되는 본문에만 `leading-relaxed`를 허용한다. 그 외에는 기본 행간.
- 줄바꿈은 단어 단위가 기본이다. 한 줄 유지가 필요하면 `truncate`.
- 밑줄은 **링크성 텍스트 버튼 전용**이다. 본문 강조에 쓰지 않는다. 취소선은 원가 표기에만 쓴다.
- 색은 타이포가 아니라 Color 역할로 정한다(제목=Text, 보조=Muted).

# Spacing

Tailwind 기본 스케일에서 **5단계만** 고른다. (`1` = 4px)

| 별칭   | Tailwind | px   | 용도                              |
| ------ | -------- | ---- | --------------------------------- |
| **xs** | `1`      | 4px  | 아이콘과 라벨, 배지 내부          |
| **sm** | `2`      | 8px  | 밀접한 요소 간격, 인풋 내부       |
| **md** | `3`      | 12px | 카드 패딩, 리스트 아이템 간격     |
| **lg** | `5`      | 20px | 화면 좌우 거터, 카드 사이 큰 간격 |
| **xl** | `8`      | 32px | 섹션 사이                         |

규칙:

- 이 5개 값만 `p-*` `m-*` `gap-*`에 쓴다. 그 외 값이 필요하면 규칙 위반을 의심한다.
- **화면 좌우 거터는 모든 표면 공통 `px-5`(20px)로 고정**한다. 화면마다 다르게 두지 않는다.
- 예외는 컴포넌트 고유 치수뿐이다(`h-14` 크롬 높이, `h-11` 컨트롤 높이, `px-1.5 py-0.5` 배지).
- 임의 값(`p-[13px]`)은 고정 레이아웃 오프셋 외에는 쓰지 않는다.

# Border Radius

| 별칭     | 클래스         | px  | 적용                             |
| -------- | -------------- | --- | -------------------------------- |
| **sm**   | `rounded-sm`   | 4   | 배지, 태그                       |
| **md**   | `rounded-lg`   | 8   | 버튼, 인풋                       |
| **lg**   | `rounded-xl`   | 12  | 썸네일, 작은 컨테이너            |
| **xl**   | `rounded-2xl`  | 16  | 카드, 모달 패널, 바텀시트        |
| **full** | `rounded-full` | —   | 아바타, 카운트 배지, 원형 아이콘 |

규칙:

- **이 5종이 닫힌 집합이다.** 임의 radius를 쓰지 않는다. 16px을 넘는 고정 라운드도 없다(그 위는 `rounded-full`).
- 중첩 시 안쪽이 항상 더 작다. 카드(16) 안 썸네일(12), 썸네일(12) 안 배지(4).
- 한 컴포넌트에서 모서리마다 다른 라운드를 주지 않는다. 예외는 바텀시트 상단뿐이다.

# Elevation

그림자는 **깊이 표현이 아니라 역할 표시**다. 숫자가 아닌 역할 이름으로 고른다.

```css
@theme {
  --shadow-flat: 0 1px 2px oklch(0 0 0 / 6%);
  --shadow-header: 0 4px 6px oklch(0 0 0 / 4%);
  --shadow-dock: 0 -4px 8px oklch(0 0 0 / 6%); /* Y 음수 — 위로만 */
  --shadow-raised: 0 2px 16px oklch(0 0 0 / 8%);
  --shadow-sheet: 0 4px 20px oklch(0 0 0 / 32%);
}
```

| 토큰            | 역할                                                              |
| --------------- | ----------------------------------------------------------------- |
| `shadow-flat`   | 컨테이너와 배경의 구분 **보조**. 단독으로 강조 용도 사용 금지     |
| `shadow-header` | 상단 고정 Header. **스크롤이 헤더 높이(56px)를 넘을 때만** 노출   |
| `shadow-dock`   | 하단 고정 바(Bottom Navigation, CTA 독). 위 방향으로만 던진다     |
| `shadow-raised` | 영역 전체가 터치 타깃인 카드, 다이얼로그                          |
| `shadow-sheet`  | 바텀시트. 이 시스템에서 가장 강한 강조                            |

**쓰는 경우**

- 스크롤되는 콘텐츠 위에 겹쳐 고정되는 표면
- 카드가 통째로 눌리는 인터랙티브 요소임을 알릴 때
- 모달·시트처럼 레이어가 실제로 위에 있는 것

**쓰지 않는 경우**

- 정적인 섹션, 컨테이너, 배너 — 여백이나 Border로 나눈다
- 버튼, 인풋, 배지 — 어떤 상태에서도 그림자를 주지 않는다
- 카드 내부의 자식 요소 — 그림자 안에 그림자를 넣지 않는다
- 단순히 "떠 보이게" 하려는 목적 — 위계는 여백과 굵기로 만든다

blur 상한은 20px, 알파 상한은 32%다. 이보다 진하거나 퍼진 그림자는 이 시스템에 없다.

# Iconography

- **Solid(면) 아이콘이 기본이다.** 라인 아이콘을 섞지 않는다.
- **20×20 그리드**에 상하좌우 2px 패딩. 실제 작도 영역은 16×16이다.
- **곡선은 정원(正圓)만** 쓴다. 자유곡선·blob 형태는 어휘 밖이다.
- **비대칭 라운딩** — 바닥에 닿는 아랫부분 각은 직선, 위를 향하는 윗부분 각은 곡선으로 처리한다.
- 부득이한 라인 표현은 stroke 2px, 면 안의 묘사선은 1.5px.
- 화살표는 라인 2px + 꼭짓점 라운드.
- **새 아이콘 라이브러리를 추가하지 않는다.** 인라인 SVG로 직접 작도하고 `currentColor`로 색을 상속받는다.
- 네이밍은 동사가 아니라 명사(`TicketIcon`, `ReceiptIcon`). 대치되는 짝은 `No` 접두(`NoPictureIcon`).

# Layout Rules

이 프로젝트에는 표면(surface)이 셋이고, 각각 레이아웃 규칙이 다르다.

| Surface  | Layout           | 구성                       | 기준 화면 |
| -------- | ---------------- | -------------------------- | --------- |
| Customer | `CustomerLayout` | Header + Bottom Navigation | 모바일    |
| Owner    | `OwnerLayout`    | Sidebar                    | 데스크톱  |
| Auth     | `AuthLayout`     | 중앙 정렬 단일 컬럼        | 모바일    |

## Page Width

- Customer / Auth: `w-full max-w-[480px] mx-auto`. 480px는 데스크톱에서 모바일 화면을 유지하기 위한 상한이며 breakpoint가 아니다.
- Owner: 상한 없이 사이드바를 제외한 잔여 폭을 채운다.
- 좌우 거터는 모든 표면 공통 `px-5`(20px).

## Header (Customer)

- 높이 `h-14`(56px) 고정, 1행 구조.
- 상단 고정(`fixed top-0`). 고정 시 본문에 헤더 높이만큼 상단 오프셋을 준다.
- 배경은 Surface. 기본 상태에서는 그림자 없음, **스크롤이 56px을 넘을 때만** `shadow-header`.
- 안에 들어가는 것은 로고와 아이콘 액션까지다. 필터·탭·검색은 헤더가 아니라 본문 최상단에 둔다.

## Sidebar (Owner)

- `lg` 이상에서만 노출. 폭 `w-60`(240px) 고정, 세로 전체 높이.
- 우측 경계는 그림자가 아니라 **Border 1px**로 나눈다.
- `lg` 미만에서는 사이드바를 숨기고 본문을 전폭으로 둔다. 모바일 드로어는 MVP 범위 밖이다.

## Bottom Navigation (Customer)

- 높이 `h-14`(56px), 하단 고정. 탭은 **최대 5개**, 각 탭은 아이콘 + 라벨 1줄.
- 활성 탭은 Primary, 비활성은 Muted. 색만으로 구분하지 말고 `aria-current`를 함께 준다.
- iOS 홈 인디케이터 대응으로 `pb-[env(safe-area-inset-bottom)]`를 붙인다.
- `shadow-dock`을 쓴다(위 방향 그림자).

## Main Content

- 고정 크롬(Header / Bottom Navigation)이 있는 화면은 본문에 **상하 오프셋을 직접** 준다. 크롬 높이 + 여백(`3`)이 기준이다.
- 단일 컬럼이 기본이다. 다중 컬럼은 Owner 표면에서 `lg` 이상일 때만 허용한다.
- 스크롤은 페이지(window) 단위로 둔다. 내부 스크롤 컨테이너는 모달 본문에만 허용.

## Vertical spacing

- 같은 묶음 안의 요소 간격: `gap-1` ~ `gap-2` (4~8px)
- 리스트 아이템 사이: `gap-3` (12px)
- 라벨과 입력, 제목과 본문 사이: `gap-2` (8px)
- 간격은 부모의 `gap`으로 만든다. 자식에 `mt-*`/`mb-*`를 흩뿌리지 않는다.

## Section spacing

- 섹션 사이: `gap-8` (32px)
- 섹션 제목과 그 내용 사이: `gap-3` (12px)
- 섹션 구분에 구분선(`hr`)이나 그림자를 쓰지 않는다. **여백만으로** 나눈다. 배경 대비가 반드시 필요할 때만 Background/Surface를 교차시킨다.

# Component Rules

구현이 아니라 **일관성 규칙**이다. 모든 공용 컴포넌트는 `src/shared/ui/<Name>/`에 위치하고 `index.ts`로 재노출한다.

공통 규칙:

- 색·간격·라운드는 반드시 이 문서의 스케일에서 고른다.
- 상태는 `default` / `hover` / `active` / `disabled` / `focus-visible` 다섯 가지를 기본으로 고려한다.
- `disabled`는 투명도만 낮추지 말고 Muted 계열 색을 쓰고 `cursor-not-allowed`를 함께 준다.
- 크기 변형은 최대 2종(`md` 기본, 필요 시 `sm`)까지만 만든다.

## Button

- 위계는 **3종만**: `primary`(화면당 1개 권장) · `secondary`(보조 액션) · `ghost`(취소·닫기 등 최소 강조). 파괴적 액션은 `primary`에 Danger 색을 얹는다.
- 높이 `h-11`(44px) 기본, 컴팩트 컨텍스트에서만 `h-9`. 라운드 `rounded-lg`. 라벨은 UI Label.
- 아이콘은 라벨 왼쪽에만 붙인다. **오른쪽 아이콘은 화살표 계열만** 허용한다(이동·상세 보기 의미).
- 아이콘만 있는 버튼은 `aria-label` 필수.
- **버튼에 그림자를 쓰지 않는다.**

## Card

- 컨테이너 역할. `rounded-2xl`, 내부 패딩 `p-3`(12px), 배경은 Surface.
- 카드 전체가 하나의 터치 타깃이면 `<button>`으로 감싸고 `shadow-raised`를 쓴다.
- 클릭 불가한 정보 카드는 그림자 없이 Border 1px 또는 `shadow-flat`으로 구분한다.
- **카드 안에 카드를 중첩하지 않는다.** 카드 내부 요소에는 그림자를 주지 않는다.
- `<button>` 내부에는 phrasing content(`span`, `img`, `svg`)만 넣는다. `div`/`p`/`h*`는 HTML content model 위반이다.

## Badge

- 텍스트 라벨 전용. 한 단어~짧은 구까지만. `rounded-sm`, 패딩 `px-1.5 py-0.5`, UI Label.
- 종류는 2종: **강조형**(Primary 배경 + 흰 전경) · **정보형**(`fill-100` 배경 + Text 전경).
- **강조형은 화면의 핵심 기능(리뷰 이벤트/티켓)에 우선 배정**한다. 아무 데나 붙이면 강조가 죽는다.
- 카운트 배지(아이콘 위 숫자)는 `rounded-full`, 두 자리 초과 시 `99+`로 절삭, Surface 색 링으로 배경과 분리한다.

## Input

- 높이 `h-11`(44px), 라운드 `rounded-lg`, Border 1px.
- 포커스 시 테두리를 Primary로 바꾼다. `outline-none`만 주고 대체 표시를 생략하지 않는다.
- 라벨은 placeholder로 대체하지 않는다. 라벨 필수, placeholder는 예시 용도.
- 에러는 테두리 색 + 하단 메시지 1줄을 **함께** 쓴다(색 단독 금지). 메시지는 Caption + Danger.
- 입력 성공 상태는 만들지 않는다. 불필요한 시각 노이즈다.
- 입력 유형을 알 수 없으면 한글 입력을 기본으로 상정한다.

## Modal

- 오버레이는 검정 반투명 1종만. **배경 블러를 쓰지 않는다.**
- 패널은 `rounded-2xl`, `shadow-sheet`, 좌우 여백을 뺀 유동 폭(`max-w-[400px]`).
- 구조는 제목 / 본문 / 액션 3단 고정. 액션 버튼은 최대 2개.
- 오버레이 클릭과 `Esc`로 닫힌다. 열려 있는 동안 배경 스크롤을 잠근다.
- 모달 위에 모달을 띄우지 않는다.

## List Item

- 기본은 좌측 미디어(정사각) + 우측 텍스트의 1행 구조.
- 미디어는 정사각 고정, `rounded-xl`. 이미지가 없으면 `fill-100` 배경 + 아이콘 플레이스홀더.
- 텍스트 영역은 **최대 3줄**: 제목 / 메타 / 보조. 제목은 `truncate`, 배지는 `shrink-0`.
- 리스트는 `<ul>`/`<li>`로 마크업한다. `div` 나열로 대체하지 않는다.
- 아이템 사이 구분선을 쓰지 않는다. 간격(`gap-3`)으로 나눈다.
- 빈 상태 문구를 항상 정의한다.

# Responsive Rules

Tailwind 기본 breakpoint만 쓴다. 커스텀 breakpoint를 추가하지 않는다.

| 구간        | 폭         | Customer                                       | Owner                                     |
| ----------- | ---------- | ---------------------------------------------- | ----------------------------------------- |
| **Mobile**  | ~639px     | 기준 화면. 단일 컬럼, 고정 Header + Bottom Nav | 사이드바 숨김, 전폭 단일 컬럼             |
| **Tablet**  | `md:`768+  | 레이아웃 변화 없음. 480px 중앙 정렬 유지       | 여전히 단일 컬럼. 거터만 넓힘             |
| **Desktop** | `lg:`1024+ | 레이아웃 변화 없음. 좌우는 Background로 채움   | 사이드바(240px) 노출, 본문 다중 컬럼 허용 |

규칙:

- 모바일 스타일을 무접두사로 작성하고, 확대할 때만 `md:` `lg:`를 덧붙인다. `max-*` 접두사는 쓰지 않는다.
- **Customer 표면은 반응형 분기를 만들지 않는다.** 폭이 커져도 480px 모바일 프레임을 유지한다. 분기 축은 화면 폭이 아니라 표면(Customer/Owner)이다.
- 반응형으로 요소를 숨기지 않는다(`hidden lg:block`). 예외는 Owner 사이드바 하나뿐이다.
- 이미지·미디어는 `max-w-full`. 폭을 px로 고정하지 않는다.
- 가로 스크롤이 생기면 그 자체가 버그다. 넘치는 콘텐츠는 줄바꿈하거나 `truncate` 처리한다.
- 폭이 아니라 **스크롤 위치로 분기하는 규칙이 하나 있다** — Header 그림자(56px 임계).

# Content & Copy

문구도 디자인의 일부다. 최소 규칙만 지킨다.

- 기본 어조는 **'해요'체**다. 특히 에러·안내는 '합니다'체 대신 '해요'체로 거리감을 줄인다.
- 중학교 1학년이 이해할 수 있는 수준으로 쓴다. 사용자는 스캔하듯 읽는다 — 단문을 쓴다.
- **버튼 라벨은 짧은 명사형 종결**을 지향한다(`객실 선택`, `적용`). 여러 버튼을 나란히 둘 때 어미를 섞지 않는다.
- 결제 버튼만 예외로 항상 `결제하기`를 쓴다. 사용자가 무엇을 누르는지 분명해야 한다.
- 지시형(`연락하세요`)과 확신할 수 없는 표현(`안심하세요`, `빠르게 처리해드릴게요`)을 쓰지 않는다. 대신 소요 시간을 정확히 안내한다.
- 혜택 취득에는 `다운로드`가 아니라 **`받기`**를 쓴다.
- 나열 구분자: 속성은 가운뎃점(`분식・한식`), 날짜 범위는 하이픈, 시간 범위는 물결표.
- 빈 상태 문구는 상황을 설명하고 다음 행동을 제시한다. `데이터 없음` 같은 개발자 문구를 노출하지 않는다.

# Do's and Don'ts

**Do**

- 강조는 Primary 하나로 수렴시킨다.
- 위계는 여백과 굵기로 만든다.
- 표면 위계는 blur 크기가 아니라 **역할명 그림자**로 고른다.
- 컨트롤 텍스트는 UI Label로 본문과 분리한다.
- 간격은 부모 `gap`으로 만든다.
- 아이콘은 인라인 SVG + `currentColor`로 해결한다.

**Don't**

- 유채색에 임의 투명도를 적용하지 않는다. 연한 색이 필요하면 `brand-50/100`을 쓴다.
- 그라디언트·glassmorphism·glow·배경 블러를 쓰지 않는다.
- Radius / Spacing 스케일 밖의 임의 값을 쓰지 않는다.
- `shadow-flat` 하나로 UI를 강조하지 않는다. 강조가 필요하면 `shadow-raised` 이상으로 올린다.
- 버튼 오른쪽에 화살표 외 아이콘을 넣지 않는다.
- `tracking-*`을 지정하지 않는다.
- 밑줄을 본문 강조에 쓰지 않는다.
- 커스텀 breakpoint를 추가하지 않는다.
- **레퍼런스의 도메인 개념을 가져오지 않는다.** 참고 자료는 여행·숙박 서비스라 대실/찜/멤버십 티어 같은 개념이 섞여 있다. 차용할 것은 accent 수렴·조밀한 타입 스케일·역할명 그림자·Solid 아이콘 조형이라는 **시각 언어**뿐이다.
- 레퍼런스의 벤더 토큰 접두사(`yds-*`)나 시스템 이름을 코드·카피·클래스명에 넣지 않는다.

# Future Components

**앞으로 만들 모든 공용 컴포넌트는 구현 전에 이 문서를 먼저 확인한다.** 새 컴포넌트는 이 문서의 규칙 조합으로 설명될 수 있어야 하며, 설명되지 않는다면 컴포넌트가 아니라 이 문서를 먼저 고쳐야 한다.

구현 전 체크리스트:

1. `src/shared/ui/`에 이미 비슷한 것이 있는가? 있으면 새로 만들지 말고 확장한다.
2. 두 곳 이상에서 쓰이는가? 한 곳에서만 쓰이면 해당 페이지 폴더에 둔다.
3. 쓰는 spacing / radius / shadow / typography가 전부 이 문서의 스케일 안에 있는가?
4. 색을 역할 이름으로만 참조하는가? 컴포넌트에 hex가 있으면 실패다.
5. `default` / `hover` / `active` / `disabled` / `focus-visible` 상태를 정의했는가?
6. 터치 타깃이 44×44px 이상인가? 아이콘 단독 버튼에 `aria-label`이 있는가?
7. 새 의존성 없이 만들 수 있는가? 아이콘은 인라인 SVG로 해결한다.
8. 시맨틱 태그를 썼는가? (리스트는 `ul`/`li`, 버튼은 `button`, 내비는 `nav`)

문서를 벗어나야 할 때:

- 규칙이 현실과 맞지 않으면 **컴포넌트에 예외를 넣지 말고 이 문서를 먼저 수정**한 뒤 구현한다.
- 새 토큰이 필요하면 `src/index.css`의 `@theme`에 추가하고, 이 문서에도 같이 반영한다.
- 예외는 문서화된 것만 유효하다. 코드에만 존재하는 예외는 규칙 위반이다.

# ReviewTicket AI

리뷰 사진 검증용 모델. 백엔드(`/api/reviews`)가 사진이 첨부된 리뷰를 받으면
이 모델로 먼저 검증하고, 통과해야 저장한다.

## 사용 모델

`facebook/dinov2-base` (Meta AI, 자기지도학습, 파인튜닝 없이 zero-shot 사용)

- 사장님이 메뉴 등록 시 올린 사진(confirmed)과, 손님이 리뷰에 올린 사진(review)을
  이미지 임베딩으로 변환해 코사인 유사도로 비교한다.
- 판정 기준(임계값): **0.80**
  - 목적이 "주문한 메뉴와 다른 음식을 찍어 올리는 것"을 막는 것이므로,
    다른 음식인데 통과되는 오류(false accept)를 최소화하는 쪽으로 임계값을 잡았다.
  - 반대로 같은 음식인데 거부되는 오류(false reject)는 기획서 정책상([FE_6]) 3분 안에
    재시도가 가능해서 상대적으로 감수 가능한 비용으로 판단했다.

### 왜 DINOv2인가

처음엔 `openai/clip-vit-base-patch32`로 시도했으나, 같은 음식/다른 음식 간 유사도
간격이 0.11밖에 나지 않아 채택을 보류했다. CLIP은 이미지-텍스트 매칭용으로 학습된
모델이라 순수 이미지 간 시각적 유사도 판별에는 약하다는 게 알려진 한계다.

DINOv2는 이미지 자체의 시각적 유사도 판별에 특화된 자기지도학습 모델이라, 같은 조건
테스트에서 간격이 0.404까지 벌어졌다. 상세 테스트 결과와 근거는 아래 참고.

- 테스트 결과 리포트: https://claude.ai/code/artifact/2ef2d3bb-055c-4a4c-b045-48ee0bf7070e
- 테스트 스크립트: `clip-test/eval_menu_match_v2.py` (로컬 전용, git 미포함 - 데이터셋 용량 커서 커밋 안 함)

## 백엔드 연결 계획 (아직 미구현)

- 이 모델은 Python(`transformers`+`torch`)로 돌고, 백엔드는 Java/Spring Boot라
  같은 프로세스에 넣지 않고 **별도 서비스로 분리**할 계획이다.
- FastAPI 기반의 작은 내부 HTTP 서비스로 감싸서, 모델은 서비스 기동 시 한 번만
  로드해두고(요청마다 재로드하지 않음) `POST /similarity` 같은 엔드포인트로
  이미지 두 장(또는 경로)을 받아 유사도 점수를 돌려주는 구조를 생각하고 있다.
- 백엔드(`/api/reviews`)는 리뷰 사진 저장 직후 이 서비스를 내부 REST로 호출해서
  유사도를 받아오고, 0.80 기준으로 통과/거부를 판정한다.
- 성능: 이번 테스트에서 CPU 기준 쌍당 평균 0.295초 - 동기 호출로도 충분히 감당 가능한
  수준으로 봄(GPU 불필요, Smart App Control 문제도 회피됨).
- 최적화 여지: confirmed 사진(사장님이 메뉴 등록/수정할 때만 바뀜)의 임베딩은 그때
  미리 계산해서 캐시해두면, 실제 리뷰 검증 시점에는 review 사진 임베딩만 새로 계산하면
  되어 더 빨라진다 - 아직 설계만, 구현은 안 함.

## 서버 코드 위치 (2026-09 이동)

FastAPI 서버는 `sdk/python-inference/` 로 옮겼다. 이미지 검증 기능을 재사용
가능한 SDK 로 분리하면서, 추론 서버가 그 SDK 의 한 구성 요소가 됐기 때문이다.

| 파일 | 내용 |
|---|---|
| `sdk/python-inference/main.py` | 실제 서버. DINOv2 를 쓴다 |
| `sdk/python-inference/stub_server.py` | 계약 테스트용 스텁. 모델 없이 같은 형식으로 응답한다 |
| `sdk/python-inference/requirements.txt` | 의존성 |

이 문서는 **모델 선정 근거와 평가 기록**으로 남는다 — 왜 CLIP 이 아니라 DINOv2 인지,
왜 문턱값이 0.80 인지가 여기 있다. 서버 운영과 백엔드 연결 방법은 위 폴더를 본다.

### 엔드포인트

- `POST /similarity` — 사진 두 장, 유사도 하나. 기존 경로이며 계속 유지한다
- `POST /embed` — 사진 N장, 임베딩 N개(float32 이진). 표본 사진의 임베딩을
  백엔드가 캐시할 수 있게 하려고 추가했다. 이 문서 아래쪽 "최적화 여지"에
  적어 두었던 그 설계다
- `GET /` — 상태 확인. 모델 식별자를 함께 돌려준다
